### 5.1 نموذج حفظ طلبات التسجيل، صلاحيات RLS، ومنع الإرسال المكرر

استجابةً لتوجيهات الإدارة لضمان أمان البيانات وجودة تدفق التسجيل، تم توثيق المخطط الكامل لعملية التسجيل الإلكتروني:

#### 1. بنية جدول طلبات الالتحاق (`public.registration_applications`)
```sql
CREATE TABLE IF NOT EXISTS public.registration_applications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_name TEXT NOT NULL,
    student_age INTEGER CHECK (student_age BETWEEN 4 AND 70),
    guardian_name TEXT NOT NULL,
    guardian_phone TEXT NOT NULL,
    desired_track TEXT NOT NULL CHECK (desired_track IN ('BEGINNER', 'MEMORIZATION', 'TAJWEED', 'IJAZAH')),
    previous_memorization TEXT,
    notes TEXT,
    status TEXT NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED', 'CONTACTED')),
    ip_hash TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT chk_phone_format CHECK (length(trim(guardian_phone)) >= 8)
);
```

#### 2. منع الإرسال المكرر وضمان ثبات المعاملات (Duplicate Prevention & Idempotency)
- **على مستوى قاعدة البيانات (Database Level):**
  إنشاء فهرس فريد مشروط لمنع تكرار تقديم طلب جديد لنفس الطالب بنفس رقم هاتف ولي الأمر طالما أن هناك طلباً معلقاً (`status = 'PENDING'`):
  ```sql
  CREATE UNIQUE INDEX IF NOT EXISTS idx_reg_unique_pending_submission 
  ON public.registration_applications(guardian_phone, lower(trim(student_name))) 
  WHERE status = 'PENDING';
  ```
  عند أي محاولة إعادة إرسال مكررة، تُرجع قاعدة البيانات خطأ `23505 (unique_violation)` ليقوم التطبيق بإظهار تنبيه لطيف: *"يوجد طلب تسجيل قيد الدراسة بالفعل لهذا الطالب، سيتواصل معكم فريق القبول قريباً"*.
- **على مستوى الواجهة الأمامية (Client Debounce & Submit Lock):**
  قفل زر الإرسال فور الضغط عليه (`disabled={isSubmitting}`) لمنع النقرات المتكررة أثناء إجراء المعاملة.

#### 3. سياسات أمان مستوى الصفوف (Row Level Security - RLS)
- **صلاحية الإدخال العام (`anon`):**
  السماح بعملية `INSERT` فقط وفق شروط إدخال صارمة، مع حظر كامل لعمليات `SELECT`, `UPDATE`, `DELETE`:
  ```sql
  ALTER TABLE public.registration_applications ENABLE ROW LEVEL SECURITY;

  CREATE POLICY "Public registration insertion policy"
  ON public.registration_applications
  FOR INSERT
  TO anon, authenticated
  WITH CHECK (
    length(trim(student_name)) > 0 AND
    length(trim(guardian_name)) > 0 AND
    length(trim(guardian_phone)) >= 8 AND
    status = 'PENDING'
  );
  ```
- **حظر القراءة العامة (Data Privacy & Zero-Knowledge):**
  لا توجد أي سياسة `SELECT` متاحة للمستخدم العام (`anon`)، مما يمنع منعاً باتاً استعراض طلبات أو أرقام هواتف المتقدمين عبر الـ API.
- **صلاحيات إدارة المدرسة (`ADMIN`):**
  يحق فقط لمديري النظام (Role: `ADMIN`) استعراض وتحديث وحذف الطلبات عبر شاشة إدارة طلبات الالتحاق في المرحلة السابعة.

- [ ] **اختبار رفض الطلبات غير الصحيحة أو الناقصة (Validation).**
- [ ] **اختبار منع الإرسال المكرر لنفس الطالب ورقم الهاتف (Idempotency & DB Unique Index).**
- [ ] **اختبار صلاحيات RLS الصارمة باستخدام دور الزائر (`anon`) والمستخدم الموثق (`authenticated`).**
- [ ] **إعادة فحص Lighthouse Mobile بعد تطبيق التحميل الكسول (Code-Splitting) لرفع تقييم الهواتف إلى > 90%.**
- [ ] **التحقق من سلامة وصول محركات البحث إلى `sitemap.xml` و `robots.txt` بعد النشر.**
- [ ] **التأكد من خلو ملفات الإنتاج النهائية (Bundles) من أي مفاتيح سرية أو بيانات داخلية.**
- [ ] **تجربة الموقع وتشغيله على نطاق الإنتاج النهائي المعتمد باستخدام اتصال مشفر آمن (HTTPS).**

## 9. التوجه المستقبلي: المرحلة السابعة (بوابة الإدارة المتكاملة لمدرسة نبراس)

تم اعتماد نطاق المرحلة السابعة ليغطي بناء **بوابة الإدارة المتكاملة (Admin Portal)** مع الحفاظ الكامل على نظام المصادقة وRLS المعتمد في المرحلة الخامسة، وتشمل 10 محاور رئيسية:

1. **إدارة الطلاب وملفاتهم الأكاديمية والبيانات الشخصية.**
2. **إدارة المعلمين وتوزيع الصلاحيات وسجلات التدريس.**
3. **إدارة الحلقات والمستويات وتوزيع القاعات والمواعيد.**
4. **نظام الحضور والغياب اليومي للطلاب والمعلمين.**
5. **متابعة الحفظ والمراجعة والاختبارات الدورية وتقييم التجويد.**
6. **إدارة وتدقيق طلبات التسجيل والالتحاق الإلكترونية (المرتبطة بجدول `registration_applications`).**
7. **بوابة أولياء الأمور والربط الإلكتروني بالطلاب.**
8. **نظام الإعلانات المدرسية، الرسائل الآمنة، والتنبيهات الفورية.**
9. **لوحة التقارير الشاملة والإحصائيات البيانية التفاعلية.**
10. **الإدارة المالية، الاشتراكات الشهرية، ورسوم الأنشطة وفق الصلاحيات المحددة.**
